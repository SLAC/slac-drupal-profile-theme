# Pins: expected since Gesso 5.4.3

## Stage 1 (sprite pipeline): js/sprite.js no longer emitted (`no-longer-emitted.txt`)

- **Cause.** `svg-sprite-loader` + `svg-transform-loader` + `svgo-loader` are replaced by upstream's `svg-spritemap-webpack-plugin`, which globs `source/images/_sprite-source-files/*.svg` itself. So the `sprite.cjs` entry (whose only job was to pull the SVGs into the module graph via `require.context`) is deleted with it, as upstream does in the same release, and webpack no longer builds `dist/js/sprite.js`.
- **Proof it is inert.** Nothing loads `sprite.js`: no library, template or PHP references it (hops 7 and 19 records). Every other `dist/js` file and all of `dist/css` stay byte-identical: no module was renumbered by the entry's removal.
- **The sprite itself** (`dist/images/sprite.artifact.svg`, bytes not pinned; the structural check in `verify` is the invariant): 19040 → 18220 bytes. Symbol ids and viewBoxes 37/37 identical; `spritecmp.py` renders **all 37 symbols pixel-identical** at 512px (svgo 3.3.5 → 4.1.0 path data). Structure: the `<defs><style>.sprite-symbol-usage…</style></defs>` block is gone, the in-file `<use>` siblings lose `id`/`class` and gain `width`/`height`, and the root `<svg>` gains `fill="none"`. All of that matters only when the sprite is displayed directly as an image. Every reference in the theme is an external `<use xlink:href="…/sprite.artifact.svg#id">` (`icon.twig` ×2, `external-link.es6.js` ×2, `_MobileMenu.es6.js` ×1; nothing in `dist/css`, no `<img>`/`<object>`/`url()`). An external `<use>` clones the referenced `<symbol>`, which inherits from the `<use>`, never from the sprite's root.

## Stage 3 (dependency wave): 26 files in js/

- **Cause.** Upstream 5.4.3's tested output-generating packages: terser 5.39.0 → **5.43.1** (via `overrides.terser`, W6-D9's decision), webpack 5.98.0 → **5.101.0**, `@swc/core` 1.11.20 → **1.13.3** (rejoining upstream; F-15's pin lapses), core-js 3.41 → 3.44 (not bundled), sass-embedded 1.86.0 → 1.89.2 (`dist/css` byte-identical). browserslist 4.24.4 / caniuse-lite 1.0.30001707 unchanged: no range requires a move.
- **Proof it is inert.**
  - `behaviors.cjs`: **28/28 entries identical** (29 before stage 1; `sprite.js` is gone). `syntaxscan.cjs` against the **hop-0 baseline**: the same **55** syntax features, none new.
  - **21 files** `astequiv --names --ids` **EQUIVALENT**: terser 5.43 drops redundant parentheses (`(()=>{})` → `()=>{}`) and reallocates names; webpack IDs are unchanged.
  - **`accordion`, `dropbutton`, `tabs`**: SWC 1.13.3 leaves default parameters native, as our source writes them (`(target, duration = 500)` in `_slide.es6.js`, `s(n, e = {})`, `o(t, r, o = !1)`) instead of `void 0 === e && (e = …)`. A default applies exactly when the argument is `undefined`, the bundles are strict-mode module code (so `arguments` is unmapped either way), and default parameters were already in the hop-0 feature set. The only observable difference is `Function.length`, which nothing in the theme reads. In `accordion`, terser also swaps two local names.
  - **`header.es6.js`**: the same, plus SWC keeping one destructured parameter native (`([n]) =>` instead of `n => { let [t] = n; … }`). Destructuring was already in the baseline set.
  - **`common.js`**: (1) terser 5.39 had inlined GSAP's keyword-to-percentage helper (split on a space, swap `top`/`bottom`/`left`/`right`, map through the keyword table, join) into its only caller; 5.43.1 keeps it as a function and calls it. The body is token-for-token the same (names masked). (2) `_MobileMenu`'s `cloneBlock(t, e = "")` / `cloneMenu(t, e = "")` keep their source defaults natively (as above). (3) Redundant parentheses and renames. Nothing else differs.
  - Total `dist/js` 267,047 → 266,061 bytes.
