# Pins: expected since Gesso 5.4.3

## Stage 1 (sprite pipeline): js/sprite.js no longer emitted (`no-longer-emitted.txt`)

- **Cause.** `svg-sprite-loader` + `svg-transform-loader` + `svgo-loader` are replaced by upstream's `svg-spritemap-webpack-plugin`, which globs `source/images/_sprite-source-files/*.svg` itself. So the `sprite.cjs` entry (whose only job was to pull the SVGs into the module graph via `require.context`) is deleted with it, as upstream does in the same release, and webpack no longer builds `dist/js/sprite.js`.
- **Proof it is inert.** Nothing loads `sprite.js`: no library, template or PHP references it (hops 7 and 19 records). Every other `dist/js` file and all of `dist/css` stay byte-identical: no module was renumbered by the entry's removal.
- **The sprite itself** (`dist/images/sprite.artifact.svg`, bytes not pinned; the structural check in `verify` is the invariant): 19040 → 18220 bytes. Symbol ids and viewBoxes 37/37 identical; `spritecmp.py` renders **all 37 symbols pixel-identical** at 512px (svgo 3.3.5 → 4.1.0 path data). Structure: the `<defs><style>.sprite-symbol-usage…</style></defs>` block is gone, the in-file `<use>` siblings lose `id`/`class` and gain `width`/`height`, and the root `<svg>` gains `fill="none"`. All of that matters only when the sprite is displayed directly as an image. Every reference in the theme is an external `<use xlink:href="…/sprite.artifact.svg#id">` (`icon.twig` ×2, `external-link.es6.js` ×2, `_MobileMenu.es6.js` ×1; nothing in `dist/css`, no `<img>`/`<object>`/`url()`). An external `<use>` clones the referenced `<symbol>`, which inherits from the `<use>`, never from the sprite's root.
