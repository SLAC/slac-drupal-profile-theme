## 26 files in js/

- **Cause.** Two things at once, both proven separately below:
  1. **Toolchain.** Upstream 5.4.2's tested versions of the output-generating packages: webpack 5.89.0 → **5.98.0**, terser 5.27.0 → **5.39.0** (via terser-webpack-plugin 5.3.14), browserslist 4.22.2 → **4.24.4** / caniuse-lite 1.0.30001579 → **1.0.30001707** (forced by autoprefixer 10.4.21), core-js 3.36.1 → 3.41.0, sass-embedded 1.80.5 → 1.86.0. W6-D9 never saw most of this: its lockfile had floated earlier.
  2. **Three forced source edits** for the eslint 9 / `@forumone/eslint-config-es5` stack (no rule switched off):
     - `accordion.es6.js`: `prefer-destructuring`; the `let target` + if/else becomes W6-D9's ternary `const target = … ? event.target : event.target.parentElement`.
     - `arrow-link.es6.js`, `external-link.es6.js` (SLAC's own code): `no-useless-assignment`; `let lastTextChild = null;` → `let lastTextChild;`. Both branches that follow assign it before any read.
- **Proof it is inert.**
  - `behaviors.cjs`, pinned expectation vs this build: **29/29 entries register identical `Drupal.behaviors`**, no load errors. (The harness's `document.currentScript` is now a real-looking `<script>`: webpack 5.98's auto-publicPath runtime checks `tagName`, which the old catch-all proxy failed.)
  - `syntaxscan.cjs` against the **hop-0 baseline**: the same **55** syntax features, none new. SWC's targets moved with the new caniuse data, but no bundle needs anything `main` did not already require.
  - **22 files** (`addtocal-a11y`, `back-to-top`, `cookie-banner`, `drawer`, `dropbutton`, `dropdown-menu`, `dropdown-widget`, `embed`, `filter-modal`, `header`, `input-widget`, `lightbox`, `media-grid`, `overlay-menu`, `social-share`, `tabs`, `tooltip`, `transitions`, `views-view--toggle`, and the three unchanged 28-byte stubs): `astequiv.cjs --names --ids` **EQUIVALENT**. The ASTs are identical up to identifier names and one consistent one-to-one renumbering of numeric literals. Every renumbered literal occurs only in a webpack ID position (module-table key, `r(id)`, `r.j`, installed-chunk map, `r.O(…,[id])`). The one coincidence, module ID `97` in `header.es6.js`, is renumbered in its two ID uses, while the unrelated bundled constant `&=-97` is unchanged.
  - **`mega-menu.es6.js`, `search.es6.js`**: the renumbered IDs sort the module table differently, and webpack 5.98 mangles the export name `Z` → `A`. `modtable.cjs` (new at this hop: module entries compared as a multiset of token streams with names and numbers masked, strings kept, plus the code outside the table in order): **EQUIVALENT**.
  - **`common.js`** (5 modules, was 6): webpack 5.98's code generation.
    - 5.89 wrapped shared-chunk exports in runtime conditions (`/^(520|926)9$/.test(r.j) ? … : null`: export only in the runtimes that use the module). 5.98 drops the condition for the mobile-menu module, exports through `r.d` getters, and concatenates the one-line slug helper (old module `1954`, `t.toLowerCase().replace(" ", "-")`) into its only user. ## design-tokens.js: no longer emitted (`no-longer-emitted.txt`)

- **Cause.** webpack 5.98 writes no JavaScript file for an entry chunk made only of an `asset/source` module. `webpack.theme-config.js`'s `design-tokens` entry is exactly that. The run still emits its two real outputs, `source/00-config/_design-tokens.artifact.scss` and `_GESSO.es6.js`, and both are **byte-identical**. Upstream 5.4.2 with its own tested webpack 5.98.0 behaves the same.
- **Proof it is inert.** The old file (`expected-since-5.3.2/design-tokens.js`) is a closed IIFE that `require`s one module whose export is the YAML source as a string, and does nothing with it. Evaluated in an empty VM context it defines no globals and has no side effects. Nothing references it: no `slac.libraries.yml` entry, template or PHP; the read-only checks of the profile's custom modules and themes find only `.gitignore`/`.dockerignore` lines, which list it as a build by-product.
- `verify` now reads a `design-tokens.js` line in any `expected-since-*/no-longer-emitted.txt` as a pinned absence; if the file reappears, verify fails.
