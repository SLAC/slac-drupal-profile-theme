# Pins: expected since Gesso 5.4.4

## Stage 4 (dependency wave): 13 files in css/

- **Cause.** Upstream 5.4.4's tested `sass-embedded` **1.97.3** (from 1.89.2) and `caniuse-lite` **1.0.30001768** / `browserslist` 4.28.1 (from …707 / 4.24.4; required by `autoprefixer` 10.4.24).
  1. **Dart Sass lands the mixed-declarations change.** A declaration after a nested rule is no longer hoisted above it: `.a { color: x; &:hover {…}; outline: y }` now compiles to `.a{color:x} .a:hover{…} .a{outline:y}`. The `mixed-decls` deprecation that warned about this is retired. (The `if()` deprecation in the same release is fixed at source, byte-neutrally: see the hop plan.)
  2. **Autoprefixer drops two prefix families** for the new target set: `-webkit-hyphens` (20 selector declarations in `styles.css` / `editor-styles.css`, on headings, `.h1`–`.h6`, `abbr`, `blockquote`, `code`, `kbd`, `q`, `samp`, `tt`, `var`) and `-webkit-backdrop-filter` (`.has-open-menu .l-site-container::after` at ≥68.75em in `styles.css`, and its `mobile-menu.css` copy). The unprefixed `hyphens` / `backdrop-filter` declarations stay.
- **Proof it is inert.**
  - **`cascade3.cjs`** (new at this hop) on all 13 files. Every declaration (context, selector, property, value, importance) is present in both files, apart from the listed prefix drops, and nothing is new. For every pair in the same shorthand family with equal specificity and importance whose values conflict on a common longhand, relative document order is unchanged, **checked across all at-rule contexts** (a `@media` block can co-apply). 12 files: fully preserved. `tabs.css`: one pair, `.c-tabs__list[role=tablist] { padding-inline }` against `.c-tabs__list[role=tablist] :where(li) { padding-left: 0 }`. These can only meet on an `li` that is itself `.c-tabs__list[role=tablist]` inside another tablist; `.c-tabs__list` is only ever a `<ul>` (`tabs.twig`, and `tabs.es6.js` sets the role on that element). Controls: the tool reports an equal-specificity swap, a `@media`-versus-plain swap in the margin family, a real longhand change (`padding: 0` ↔ `padding-left: 4px`), and a dropped prefix; it passes a mixed-decls split, a move past a higher-specificity rule, and `padding: 56px 0` ↔ `padding-left: 0rem` (same value).
  - **Prefixes against the declared targets** (`last 2 versions and not dead`, `>= 1%`, `>= 1% in US`). With caniuse-lite 1.0.30001768 **none of the 29 targets needs either prefix**; the only non-supporting targets (`op_mini`, `kaios`, `and_qq`) lack the feature altogether, prefixed or not. Under the old data, iOS Safari 15.6–17.7 were targets and needed both; they have aged out of the window. Upstream's own tested data produces this output.
  - **Autoprefixer is still running**: 47 prefix families unchanged in count (e.g. `-webkit-appearance` 32, `-moz-appearance` 22, `-webkit-tap-highlight-color` 9). The only other count change is the `::-moz-range-thumb` / `::-ms-thumb` / `::-webkit-slider-thumb` selectors appearing in the extra rule blocks Sass now splits off, 8 → 10 each, with no new declaration.
  - `dist/js` and the token artifacts are byte-identical (terser 5.44.1, webpack 5.104.1 and `@swc/core` 1.15.11 are neutral here).
- **Risk.** Visitors on iOS/iPadOS Safari 15–17 lose `hyphens: none` on the listed elements (their default, `manual`, hyphenates only at soft hyphens) and the 4px backdrop blur behind the open menu at desktop widths. Flag F-23.
