## Dependencies

**Install method.** `npm install <pkg>@<upstream-tested version>` for the moved direct packages, so `package.json` keeps upstream's caret ranges while the lockfile holds upstream 5.2.0's resolutions: the 11 Storybook packages at 7.0.10, `webpack` 5.82.0, `@babel/core` 7.21.8, `@babel/preset-env` 7.21.5, `@babel/preset-typescript` 7.21.5. (First attempt went wrong in zsh, which does not word-split an unquoted variable: only `storybook` got pinned and the rest floated to 7.6.24. Reverted to `HEAD`'s lockfile and redone from bash.)

**Transitive drift, and how it was removed.** npm then re-resolved everything the moved packages needed to the newest allowed versions: 134 existing top-level packages moved, including `@babel/*` helpers 7.21 → 7.29.7, **`browserslist` 4.21.5 → 4.29.3** and **`caniuse-lite` 1.0.30001469 → 1.0.30001813**. That changed `dist/css` (autoprefixer output in `styles.css`, `editor-styles.css`, `mobile-menu.css`) and 9 `dist/js` files (Babel). Trap W1, one level down. New helper scripts undo it (`gesso-harness/lockmin.cjs`, `lockhoist.cjs`, `lockfix.sh`):
- for every top-level package that moved, restore the **previous** resolution if it still satisfies every dependent (Node's lookup), else **upstream 5.2.0's** resolution, else keep npm's;
- a newly added package takes upstream's resolution when it fits;
- **never choose a candidate inside a known advisory range** (advisories unioned from `npm audit` of the previous, upstream and npm-float lockfiles, including through-dependency ranges), except for output-generating build tooling (`@babel/*`, browserslist/caniuse-lite, postcss/autoprefixer, terser, webpack, sass, css/mini-css loaders, core-js, source maps), where the advisory is build-time only and byte-identical output wins. Those exceptions are listed below;
- hoist nested entries that have no top-level copy (see next point);
- `npm install` to reconcile, repeat to a fixpoint (3 rounds), then `npm ci`.

Result: 126 existing top-level packages moved, **109 of them to upstream 5.2.0's exact resolution**; of 140 new packages, 90 are at upstream's exact version. The rest are Storybook/jest dev tooling where upstream's version was vulnerable or unsatisfiable (e.g. `webpack-dev-middleware` stays 5.3.4, since upstream's 5.3.3 is in GHSA advisory range `<=5.3.3`; `ws` 8.22.0; `form-data` 3.0.5).

**Storybook packages left nested.** Upgrading 6.5 → 7 in place left 26 of the new 7.0.10 packages (`@storybook/channels`, `channel-postmessage`, `channel-websocket`, `client-api`, `components`, `core-common`, `csf`, `node-logger`, `router`, `store`, …) nested under their first dependent, because the old 6.5 top-level copies were still there when npm placed them, and npm never re-hoists. Storybook's generated preview entry resolves from the project root, so `build-storybook` failed with `Can't resolve '@storybook/channel-websocket'`, then `'@storybook/client-api'`. W6-D9's and upstream's lockfiles have them all top-level. `lockhoist.cjs` hoists every single-version nested name with no top-level copy; multi-version names (`fs-extra`, `minipass`, `webpack-sources`) stay nested. webpack keeps its own nested `webpack-sources` 3.2.3, as at `main`.

**Advisories.** `npm audit --package-lock-only`: 113 → **85** (npm's unconstrained float would have given 84). Kept inside an advisory range on purpose, all build-time only and recorded for F-08:
- **webpack 5.82.0**: GHSA-4vvj-4cpr-p986 (moderate, `<5.94.0`, DOM-clobbering gadget in the auto-publicPath runtime). The gadget is emitted **only into `dist/js/sprite.js`**, which exists to make webpack write the sprite artifact and is loaded by no library or template (the same code was already in the baseline under 5.76.3). The two low `buildHttp` advisories (`<=5.104.0`) are build-time and `buildHttp` is not used. Upstream's own lockfile stays below 5.94 until 5.4.2; `sprite.js` goes away at 5.4.3 s1.
- **@babel/helpers 7.21.5**: GHSA-968p-4wvh-cqc8 (moderate, `<7.26.10`) is inefficient generated code for **named capture groups in `.replace`**. Our source has no named capture groups (`grep '(?<'` over `source/**/*.js` is empty), so the affected helper is never emitted. The baseline had 7.21.0, also affected.
- **browserslist 4.21.5** (`main`'s): GHSA-73wf-gq98-2v4g, GHSA-c83g-rgw3-j3cx (custom stats files, query-cache memory): build-time only, static queries from `package.json`. Moving it would change caniuse data and therefore autoprefixer output.
