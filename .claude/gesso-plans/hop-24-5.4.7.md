### The ESLint coupling

As in W6-D9: upstream's new `eslint.config.js` fails to load under 3.0.7 (`Cannot redefine plugin "react-hooks"`, the plugins registered twice), and 3.0.9 fixes it. The widened script lints **43 files** (was 40): the 40 `.js`, `05-pages/page-wrappers/default.jsx`, `06-utility/storybookHelper.jsx` and `@types/drupal/index.d.ts`. SLAC has no `microsite.jsx` and no `eslint-disable … react/prop-types` directive, so W6-D9's edits don't apply. What the new scope finds instead is 2 errors on one line of `default.jsx`: `alertBarPlayFn` is imported and never used (`@typescript-eslint/no-unused-vars`), and the line is too long (`prettier/prettier`). `alert-bar.stories.jsx` never exported `alertBarPlayFn` (the reconcile recorded it as pre-existing, `reconcile-vs-f712137.md`), so the binding was always `undefined`. Dropping the name keeps the module import for `AlertBar`, so the Storybook module graph is unchanged. Stories are still excluded, so W3 stands. Flag F-30.

`npm run build` is unaffected either way: `eslint-webpack-plugin` sees only webpack-graph modules.
