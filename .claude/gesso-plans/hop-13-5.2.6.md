## Forced edits

1. **`source/03-components/button-group/_button-group.scss`**: `&:focus-within, &:hover` → `&:hover, &:focus-within`. The rewritten plugin makes the old order a violation, which fails `npm run build` (stylelint-webpack-plugin). Our file was byte-identical to upstream 5.2.5's; this is **upstream's own 5.2.6 fix**, applied with `git apply`. Output: one selector list reordered in `styles.css` and `editor-styles.css` (pinned).
2. **`source/03-components/site-name/_site-name.scss`** (SLAC-only): the plugin now accumulates pseudo-class order across **sibling** rules in one block, so `.c-site-name__acronym`'s two separate `:hover/:focus/:active` groups (`.c-site-name:hover &…` and, three rules later, `.c-site-name--logo:hover &…`) read as `hover, focus, active, hover, …` and fail the build. The second group moves into its own `.c-site-name__acronym { }` block (one-line comment says why). Sass emits the same rules in the same order, so **CSS is byte-identical**; no rule is disabled. W6-D9 had no such file.
